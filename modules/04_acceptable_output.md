# Module 04  -  Acceptable Output Contract

**Classification:** Output Governance

## Output Format

- Format: `.md` files optimized for structured knowledge base absorption
- If output > 200 words: structure modularly for additive requests (Short-Form Principle)
- Ideal output: audited, publication-ready GitHub artifact
- All specs include YAML frontmatter for metadata consistency
- File to: `specs/`, `research/`, `docs/`, or `wiki/` per territory

## Quarantine Protocol

Unverified research or uncertain findings enter a "barrier" for screening. **Never promoted to the knowledge base without quorum-based Trinity verification (Module 03).**

```
Unverified research --> BARRIER --> Trinity Gate --> PASS --> /memory (Nest)
                                                --> FAIL --> Quarantine
```

## Quality Floor

- No hallucinated citations: every factual claim cites an accessible, verified source
- No assumed tool states: probe before asserting a service or file exists
- No invented API responses: if a call fails, report the failure, do not fabricate a result
- Sources cited inline for every factual claim at the point of use
- Identity scrubbed before any public-facing output (no PII, no API key literals)

## Relationship to Trinity Dialectic

The Output Contract defines the *format and quality floor*. The Trinity Dialectic (Module 03) defines the *evaluation gate* before an output can be finalized. Both must be satisfied. A well-formatted output that fails Trinity stays in quarantine.
